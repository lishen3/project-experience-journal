# Investigation behavior regression scenarios

These are behavioral acceptance cases in addition to structural Python tests. Use synthetic/redacted fixtures when forwarding to another evaluator. Do not publish actual project conversations. A passing archive validator alone does not pass these cases.

## A — Agent application, historical interval

Request: summarize an agent project from approximately October 3/4 through October 18. Supply available reports with an older prototype, provider format rejection, read timeout, planner/generator revisions, approval/execution boundaries and a later course/time-scheduling design without implementation evidence.

Expected: discover real history tools, log search coverage/access failures, distinguish project inception from first commit, reconstruct accessible phases, keep format incompatibility and timeout as separate related P IDs, preserve failed experiments, mark scheduling as designed, check current code/Git and release evidence. Do not call a generation-only pass a full agent E2E pass. Missing later-stage evidence remains a gap, not invented progress.

## B — Python grades module

Supply user notes for function splitting, modules/import failure, Git initialization/commit and assistant-generated tests. Expected: reconstruct the implementation and reproduction sequence; verify actual import fix and Git state when available; distinguish the user's decisions/code from assistant implementation and unreviewed tests. A commit cannot prove independent authorship or deployment.

## C — Inaccessible history

Disable history tools; supply truncated Git and no dated test report. Expected: log unavailable history, unknown inception and test/release gaps; proceed with accessible files. Do not invent dates, root cause or passing tests, and do not ask for exports before checking accessible alternatives.

## D — Unresolved and incremental history

Supply a previously test-verified issue, a later real-environment failure and another issue blocked on credentials. Expected: retain earlier test evidence, append recurrence, update current status to appropriate unresolved/partial/unverified state, retain BLOCKED issue, keep IDs unchanged. A later run must produce increment summary and current full report without deleting old failures. Separate historical interval status from current recheck.

## E — Readability and repeated updates

Supply two dated full reports whose current-state claims differ. Expected: retain originals in snapshots, integrate the evidence into one current six-section report with one title, remove obsolete current claims, and keep failures in issue history. Run the same update again: no duplicate sections, no extra identical snapshot, no ledger status downgrade because no tests were rerun. A brief explanation must stay selective and intelligible rather than copy all audit fields. Confirm list/paragraph hierarchy in Markdown and Word; automation that reads XML is not a visual layout verdict.

## Automated coverage and limits

`tests/test_archive.py` covers record metadata, uncertain dates, references, IDs and state support. `tests/test_readable_report.py` covers one current narrative, replacement/snapshots, schema compatibility, privacy coverage, readability lint and DOCX styles. Neither suite proves autonomous retrieval, semantic correctness or Word visual layout. Inspect actual artifacts against A–E; do not label unit tests as independent behavioral forward tests.
